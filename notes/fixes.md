Tokens have `admin`, `deploy` or `read` roles and an app allowlist (`*` for every app). `GET`/`POST /auth/tokens` list and create them; the create response is the only place the bearer appears, and `DELETE /auth/tokens/<id>` revokes it. `deploy` tokens can deploy, roll back code, restart/stop/start and read non-sensitive app metadata in scope, but cannot touch config, secrets, backups, databases or deletion; `read` tokens are limited to non-sensitive `GET` routes, and `/events` stays admin-only. `/login` accepts scoped tokens and rate-limits five failures per remote host per minute. 16. [x] **Forwarded headers and host trust.** Inbound `X-Forwarded-For`, `X-Forwarded-Proto` and `X-Forwarded-Host` are now ignored unless the immediate peer matches `WT_TRUSTED_PROXIES` (comma-separated IPs/CIDRs). For a trusted proxy the supervisor resolves the client from the rightmost non-proxy XFF address, accepts only `http`/`https`, and uses a validated first `X-Forwarded-Host` for routing, `Host`, `spin-full-url` and the forwarded headers. It replaces the inbound XFF chain instead of copying it, sets `X-Real-IP`, removes `Forwarded`, and uses the resolved client for cookie `Secure`, login rate limiting and audit entries. A trusted proxy must replace client-supplied forwarded headers rather than append to them; there is no PROXY protocol or per-hop limit. `932de9e` and `fdac5ed` implement and document it.

17. [x] **Hosts and ingress.** The supervisor reserves `localhost`, IP literals, the app-domain root and both listener hostnames, validates DNS labels, supports `hosts` aliases and single-label `*.apps.example.com` patterns, rejects overlapping host patterns, and serves wildcard aliases through the existing certificate files. Use a wildcard certificate and DNS record to avoid one ingress per app.

18. [x] **Network and app-to-app calls.** A loopback internal listener (`WT_APP_FETCH_LISTEN`, default `127.0.0.1:0`) serves `/apps/<target>/<path>`. Apps get `WT_APP_FETCH_URL`, `WT_APP_NAME`, `WT_APP_TOKEN` and `WT_APP_URL_<NAME>`; `WT_STORAGE_TOKEN` remains the same credential. The caller authenticates with its own token, the target's `allow_callers` list is checked, and the forwarded request carries an HMAC-signed `X-WT-App-Caller` identity plus timestamp. `app.NewAppRequest` and `app.Caller` wrap both sides, and a token for an app that is no longer registered is rejected. Untrusted egress now also allows the internal listener and explicit IPv4 TCP `egress` CIDR/port rules, still installed per app UID before readiness. Remaining limits: there is still no network namespace, trusted mode keeps unrestricted `inherit`, egress is IPv4 TCP only, DNS is not automatically allowed, the signature does not cover the body, and a target that never calls `app.Caller` is trusting the internal listener alone.

19. [x] **Fix the HTTP adapter's net/http contract.** `packages/wasihttp` now sets `Host`, `RemoteAddr`, `RequestURI`, `URL.Scheme`, `URL.Host` and `TLS` from `spin-full-url`, `spin-client-addr` and the forwarded/host fallbacks, keeps `X-Request-Id`, and cancels the handler context when a response write finds the client stream dropped. Outgoing requests stop the body copier on cancellation, turn the context deadline into `wasi:http` connect/first-byte/between-bytes timeouts, and `wasihttp.NewClient()` defaults to 30 seconds. Limits: there is no disconnect signal before the first response write, a cancellation without a deadline is noticed before a send and after it returns but cannot interrupt an already blocked `wasi:http` call, `wasihttp.Get`/`Post` still send without a default client timeout, and request IDs travel only as headers, not in the context.

A `wt:log` WIT import, a log index, sampling and automatic request-ID propagation through the storage client remain follow-ups.

Added `GET /apps/<name>/deployments/<id>` for one history entry with status/error/current, `POST /apps/<name>/validate` as the explicit dry-run form, bundle `ETag` plus `If-None-Match` for conditional deploy, `Idempotency-Key` replay for 24 hours, and config `ETag`/`If-Match`/`If-None-Match`. A hand-maintained OpenAPI document is at `wt/openapi.yaml`. Still open: deploy is synchronous, so there is no queued deploy resource with cancel or live logs; the OpenAPI client and SDK generation is not wired in; and the older config/backup request fields still use snake_case while newer resources use camelCase.

23. [ ] **Cron semantics.** Support cron expressions or at least time zones, jitter, catch-up policy, concurrency policy, headers/body, a manual trigger and last/next-run state. Scheduled calls currently bypass `max_concurrency` and the access log, which makes both limits and logs misleading.

24. [x] **A standalone SDK and CLI.** `wt new` now works outside `wt/example`: standalone scaffolds copy an embedded `sdk/` tree (app, storage, wasihttp, httpmeta, WIT and `generate.sh`), write `go.mod`/`go.sum` with `replace wt.packages => ./sdk`, and use `go tool componentize-go` from the app module. `--module` and `--sdk PATH` override the module and SDK source, and `TestEmbeddedSDKMatchesPackages` keeps the embedded copy honest. The binary now has `apps`, `logs` (server-side filters and SSE follow), `deploy`, `build`/`bundle`, `dev`, `new`, `rollback`, `backup`, `config`, `open` and `completion`, with `--json`, `--host`, `--token` and a `~/.config/wt/config.json`/`WT_CONFIG` file. The SDK is vendored rather than published as a semver module, and generated clients are still not emitted; the pinned Containerfile remains the reproducible build image.

25. [ ] **Prove the interface is language-agnostic.** Add a Rust (or JavaScript) example built against the same WIT world. A Go-only SDK leaves the WASI contract and the adapter assumptions untested.

26. [x] **Static, compression and realtime.** Static files with sibling `.br` or `.gz` sidecars are served precompressed when the request accepts the coding, with the original `Content-Type`, `Content-Encoding` and `Vary: Accept-Encoding`; the original file must exist and `.br` is preferred. Proxied `application/json`/`+json` responses are gzipped when accepted, except SSE, `no-transform`, already encoded and known responses of 256 bytes or less. README documents that WASI HTTP and `wasmtime serve` have no WebSocket upgrade path, that SSE works through the proxy and is the supported realtime path, and that a host WebSocket bridge is not implemented.

## P4: developer experience and testing

27. [x] **Fix `wt dev`.** Dev now serves the app at `<name>.localhost:<app-port>` and runs the panel on a separate `WT_ADMIN_LISTEN` at `127.0.0.1:<app-port+1>` (`--admin-port` overrides). `--workspace DIR` builds and deploys every immediate child app with an `app.json`, giving each `<name>.localhost` on one supervisor and one state tree so app-to-app fetch and storage work. `--app-host` remains single-app only. Watch mode runs per workspace app.

28. [x] **Make frontend-only deploys cheap.** `wt-deploy` hashes component inputs into `.wt-build.json` and skips the build and compile when they are unchanged and `main.wasm` exists; `--force-build` overrides. If the server already runs the same wasm digest, the client sends `X-WT-Static-Only: 1` with only `app.json` and `static/`, and the supervisor copies its current component before the static swap. Uploads print coarse progress percentages. Resumability is not implemented.

29. [x] **Logs.** Logs already support server-side `level`, `source`, `q`, `since` and `until` filters, `GET /apps/<name>/logs/export`, request IDs in access lines and storage changes, and SSE filtering. `WT_ACCESS_LOG` (default on) and `WT_ACCESS_LOG_EVERY=N` sample successful access lines while always keeping 5xx lines. The panel still applies its text and minimum-severity filters to the loaded lines; the API can filter server-side. A `wt:log` import and a full log index remain open.

30. [x] **Test the real paths.** `wt/e2e.sh` now deploys a second app, rejects a colliding host, restarts the supervisor and checks both apps survive, and with `WT_E2E_EXAMPLES=1` also builds/deploys the scaffolded app and guestbook. `wt/e2e-image.sh` runs the same hello deploy against the musl Containerfile with podman. `BenchmarkManyAppsSnapshot` covers 200-app roster snapshots, `BenchmarkStorage*`/`BenchmarkSQLite*` cover storage throughput, `FuzzBackupArchive` covers backup extraction, and `TestFailedDeployKeepsOldProcess` plus the existing rollback-journal recovery tests cover failure recovery. The real image, scaffolded and guestbook runs are opt-in and require wasmtime, Bun and podman, so they were not executed in this environment.

31. [x] **Container hardening.** The image now defaults to the non-root `wt` user (`10001:10001`), owns writable `/var/lib/wt/apps` and state directories, and can run with a read-only root filesystem. `wt/compose.yaml` sets `read_only`, `cap_drop: ALL` and `no-new-privileges`; the README shows the equivalent `podman run` flags. `TARGETARCH` selects amd64 or arm64 for both the Go supervisor and the wasmtime musl target, and the final image sets the matching `WT_WASMTIME_TARGET`. The runtime stays `scratch` and carries only the supervisor, wasmtime, CA certificates and account files. Untrusted mode still needs root, a cgroup mount and the documented capabilities; that path cannot be fully rootless. The image e2e is opt-in and was not executed in this environment.
